# Game forecasting code inventory

Audited against Drewclaw's `footy-models` workspace and GitHub `main` on 2026-10-11. Also inspected local `footy-site` (scouting UI, no independent calibrated fixture engine), `soccerdata` (cached provider data), and `fm26-data` (raw FM26 player attributes, not a match prediction implementation). These sources are distinct from market-value/transfer forecasts elsewhere in this repo.

## Production match simulation

- **`crates/match/src/second_resolved_api.rs` → `simulate_second_resolved_dynamic_mental_match`** is the intended entrypoint. The implementation in **`second_resolved_mc.rs`** samples starting XI/bench, formation, latent player event rates, score-state effects, mental dynamics, injuries, red cards, ordered same-second event collisions, substitutions, and match outcomes on a one-second clock. Its new `windows_15min` aggregation captures event incidences and score states from those *same* simulated paths, not independent Poisson goal timing.
- **`crates/match/src/specific.rs`, `simulation.rs`, `channels.rs`, `lineup.rs`, `matchup.rs`, `psychology.rs`, `dynamic_mental_mc.rs`, `second_clock.rs`** implement player-event priors, FM attribute interactions, formation/lineup uncertainty, psychology and time/event handling. Keep primitives source-neutral and deterministic.
- **`crates/match/src/calibration.rs` → `OutcomeCalibrator`** is a post-hoc temperature and draw-logit calibrator from strictly previous out-of-sample forecasts. Do not fit it on a future fixture or substitute it for the simulation's match-result mechanism.
- **`apps/matchforecast/src/main.rs`** is the original full player-level StatsBomb fixture driver. **`main_mls.rs`** adds SofaScore 2026 player stats, FM attributes, form learning, shot anchors and the production second-resolved engine. **`backtest.rs`** performs walk-forward tests. `BACKTEST_RESULTS_MLS.md` reports a Brier score of **0.7646 on only 12 fixtures**, worse than the 0.667 uniform reference; the model is **not yet validated** for strong probabilistic claims.
- **`apps/matchforecast/src/form.rs`** implements strictly historical per-player form/rate predictions and appearance learning. Related scripts: `build_player_aggregates.py`, `build_selection_training.py`, `build_form_series.py`, `join_fm_attributes.py`, `prep_backtest.py`, and `run_matchforecast_ablation.py`.

## Premier League application

- **`scripts/match_premier_league_fm26.py`** reads the official 2026–27 registered squads, matches names to FM26 unique IDs and raw attributes, and leaves ambiguities explicitly unmatched. *Club identity is authoritative from the Premier League*, not a stale FM/Transfermarkt transfer mapping.
- **`scripts/prepare_pl_player_inputs.py`** converts frozen historical PL results and matched FM attributes into input schemas understood by the existing player driver. Because a contemporaneous player-event + confirmed lineup feed is absent, participation and event rates are **explicit priors derived from FM/previous usage**. The October 9 2026 dated team-news file excludes FM-ID-confirmed injured or suspended players; doubtful players remain uncertain, not observed current PL 2026–27 per-player counts.
- **`apps/matchforecast/src/main_pl.rs`** executes the **same** second-resolved match driver with these PL inputs, reads the earlier team-model expected-goal intensities only as a scenario-level prior, and persists one complete path-aggregate result per fixture. The shared adapter is currently housed in `main_mls.rs` and should be extracted into a reusable library for a later refactor.
- **`crates/match/src/team_goals.rs`, `apps/plforecast`, `scripts/forecast_premier_league.py`** are a separate statistically refitted team-goals **benchmark**. This is *not* the player-resolved event engine and its results must not be labeled as full player simulations. It uses 2023–26 results, prior Championship season information for promoted clubs, and a conservative FM squad quality adjustment. Incremental FM Brier gain is statistically inconclusive on the 56-match holdout; see `docs/premier-league-forecast-2026-10-11.md`.

## Validation and limits

The Premier League player engine produces **simulation scenarios**, not verified 2026–27 live per-player event predictions. The input does not contain confirmed lineups, injury reports, exact player appearances, shot maps, or calibrated matchup parameters. Its 15-minute goal/card/substitution windows come directly from the second-resolved paths; statistical reliability is bounded by the number of paths, plausible roster priors and **the poor existing MLS out-of-sample result**. Do not conflate Monte Carlo precision with model calibration.

Reproduction of the current saved matchweek requires local FM26 data and football-data.co.uk results (which are not republished in Git). Run `python3 scripts/match_premier_league_fm26.py`, then `python3 scripts/prepare_pl_player_inputs.py`, then `cargo run --release -p footy-matchforecast --bin footy-matchforecast-pl -- --paths 72 --seed 42`, and finally `python3 scripts/render_pl_forecast_cards.py`. The pinned prediction artifact and README images can be inspected without running the private data pipeline.
